# Observation and repair proposals

Temporal reconciliation and the HTTP controller use `reconcileObserveOnce`, `reconcileEnvironment` and `proposeRepairs`. The worker renews its existing `reconcile:<environmentId>` lease, heartbeats, receives cancellation, and asserts the same fence before persistence, proposals and dispatch. It does not acquire a second reconcile lease. Cancelled or stale passes stop without committing a stale observation or starting another repair.

`allowAutoRepair` permits proposal consideration. It grants no execution authority. A candidate needs a real observation, managed ownership in both graph and store, a safe resource kind, hysteresis/pacing eligibility and either an actual registered `drift.repair` driver handler or admission by the shared pure declarative repair recipe. That recipe admits only the exact managed AWS ECS replica-count finding with a digest-pinned image and bounded desired/observed counts; other fields, providers, ownership and unsupported targets remain refused. Unknown, inaccessible, simulated and external targets cannot become repair proposals. Partial observations retain their unknown/inaccessible provenance; readable safe candidates remain resource-scoped.

The capability broker evaluates each proposal and records allow, approval or denial. Approval remains bound to the immutable proposal digest and a verified human browser session. An allowed operation is claimed through `beginExecution`, which rechecks current policy, scope and approvals, then dispatched to the existing day-two workflow. That workflow retains the environment mutation lease, execution credential grant, policy checks and readback verification. The observation workflow returns only counts and a digest of repair decisions, never provider responses, findings, credentials or arbitrary failure reasons.

An uncertain repair blocks its resource indefinitely. Other unresolved uncertain mutation capabilities conservatively block the environment. A cooldown does not resolve uncertainty. A truncated operation inventory fails closed rather than overlooking an older conflict. Inspect and settle the original operation against authoritative provider and workflow evidence before proposing further mutation. A running or uncertain operation is never blindly dispatched again. A lost dispatch acknowledgement is recorded as uncertain; a failed uncertainty write leaves the running claim blocking another dispatch.

New workflow histories use `patched("reconcile-canonical-proposals-v1")`. The legacy branch preserves its activity request, timeout and two-count result shape, including the historical `repair: "not_implemented"` value. Retain the patch until old histories have left retention, following [Temporal's patch lifecycle](https://docs.temporal.io/develop/typescript/workflows/versioning#patching). The dedicated SDK regression records the original definition from commit `83ec97f`, then replays it against the current bundle. A separate isolated Temporal regression exercises the shared controller with the actual control store and broker; provider reads and policy decisions in that fixture are scripted and are not cloud acceptance.

## Current limits and release blockers

No production driver currently implements a native `drift.repair` handler. The shared declarative recipe permits canonical proposal admission for its bounded AWS ECS case, but its execution adapter is still unmerged. Proposal admission does not prove executable remediation, and this composition does not complete PROD-OBS-01 remediation acceptance or offer repair as a supported service. The adapter must be integrated and verified through the existing policy, immutable full-environment saved-plan approval, execution and readback authority before that service can be offered. It must not add a direct reapply engine or infer mutation authority from the request flag.

Fresh diagnosis, fleet telemetry, durable observation/reaping schedules, operator settlement and escalation workflows, incident postmortems, and live provider remediation/readback proof remain outstanding PROD-OBS-02/03/04 work. Existing incident correlation, hysteresis, cooldown and proposal/blast limits remain in force. Source regression fixtures and replay preparation are not evidence that production repair or fleet observability is complete.
